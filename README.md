## Project Overview
This project demonstrates an automated machine learning workflow deployed entirely on Google Cloud Platform (GCP). The goal of this assignment is to train a classification model, store its artifacts, and set up an event-driven architecture that automatically generates predictions whenever new data is uploaded to a storage bucket.

The pipeline is built around the classic Iris dataset, predicting the species of a flower based on its sepal and petal dimensions. 

## Cloud Infrastructure and Architecture

The project utilizes three primary Google Cloud services:
* **Vertex AI Workbench:** Used as the primary development environment to explore data, build the machine learning model, and test initial concepts.
* **Google Cloud Storage (GCS):** Acts as the central repository for data, models, and outputs. 
* **Google Cloud Functions:** Serves as the serverless compute engine to run our inference script automatically based on storage triggers.

## Storage Bucket Structure
The GCS bucket is organized into three distinct directories to maintain a clean, separated workflow:
* **data:** This folder contains the raw input datasets. Uploading a new CSV file here acts as the trigger for the automation pipeline.
* **models:** This directory stores the serialized machine learning model artifacts (saved as `.joblib` files) after they are trained in Vertex AI. 
* **outputs:** This is the destination folder where the Cloud Function saves the final datasets containing the newly appended prediction columns.

## File Descriptions

### 1. week 1.ipynb (Model Training and Experimentation)
This is the core Jupyter Notebook developed within Vertex AI Workbench. It contains the initial machine learning workflow.
* **Process:** It handles loading the training data, preprocessing the features, and training a machine learning model (Decision Tree). 
* **Artifact Generation:** Once the model reaches satisfactory performance, it is serialized using `joblib` and uploaded directly to the `models/` directory in the GCS bucket.

### 2. inference.py (Automated Cloud Function)
This Python script is deployed as a Google Cloud Function. It is designed to be completely event-driven and automated.
* **Trigger:** The function is triggered automatically the moment a new file is uploaded to the GCS bucket.
* **Infinite Loop Prevention:** It includes logic to check the file path. If the uploaded file is placed in the `outputs/` folder or contains "predicted_" in its name, the function terminates safely to prevent an endless loop of self-triggering executions.
* **Execution:** 1. It identifies the newly uploaded dataset and reads it into a Pandas DataFrame directly from cloud storage.
    2. It scans the `models/` directory and fetches the most recently trained `.joblib` model.
    3. It extracts the necessary features (sepal length, sepal width, petal length, petal width) from the incoming dataset.
    4. It passes these features to the model to generate predictions.
    5. It appends a new column named `predicted_species` to the dataset.
    6. It saves this updated dataset as a new CSV file back into the `outputs/` directory in the GCS bucket.

### 3. outputs_predicted_data_v1.csv (Sample Output)
This file represents the final deliverable generated by the Cloud Function. It mirrors the input dataset but includes the appended `predicted_species` column, demonstrating that the automated inference pipeline ran successfully on the cloud infrastructure.

## Deployment and Reproduction Steps

If you want to recreate this environment from scratch:

1.  **Set up GCS:** Create a Google Cloud Storage bucket. Inside this bucket, create three subfolders: `data`, `models`, and `outputs`.
2.  **Train the Model:** Open `week 1.ipynb` in Vertex AI Workbench. Run the notebook cells to train the model. Ensure the resulting `.joblib` file is saved to the `models/` folder in your bucket.
3.  **Deploy the Cloud Function:** * Navigate to Cloud Functions in GCP and create a new function.
    * Set the trigger type to Cloud Storage and select the event for "On file creation". Point it to your bucket.
    * Use the code provided in `inference.py` as your main function source. Be sure to include `google-cloud-storage`, `pandas`, `joblib`, and `functions-framework` in your `requirements.txt`.
    * Ensure the function's service account has read and write permissions for the GCS bucket.
4.  **Test the Pipeline:** Upload a new, unlabeled Iris CSV dataset into the `data/` folder. Wait a few moments, then refresh your bucket and check the `outputs/` folder for your newly generated predictions file.
